# 架构

## 分层

```
┌───────────────────────────────────────────────────────────┐
│ views/            NetworkView · BoardView · OutlineView   │
│ components/       Rail · Inspector · Settings · ui        │
├───────────────────────────────────────────────────────────┤
│ store.ts          Zustand：会话、主题、视图、选区、数据快照 │
├───────────────────────────────────────────────────────────┤
│ data.ts           唯一的业务写入点（增删改 + 同步循环）      │
├───────────────────────────────────────────────────────────┤
│ cloud.ts          按环境变量选后端                          │
│   ├─ backend/local.ts   localStorage + 链式查询模拟        │
│   └─ 云 SDK             PostgREST + RLS                    │
└───────────────────────────────────────────────────────────┘
```

一条规则：**视图不直接写数据**。所有写入都经 `data.ts`，因此两种后端、三种视图共享同一份行为，改一处即可。

## 文件职责

| 文件 | 职责 | 规模 |
|---|---|---|
| `src/types.ts` | 行类型、`Kind` 枚举、`Ref` 与 key 编码 | 小，只放类型 |
| `src/store.ts` | 全局状态与派生辅助（节点度数等） | 单 store，不拆 slice |
| `src/data.ts` | CRUD、增量同步、设备、首次示例数据 | 唯一写入点 |
| `src/layout.ts` | 图构建（`buildGraph`）、力导向模拟、树形布局 | 纯函数 + d3-force |
| `src/cloud.ts` | 模式判定、客户端、错误文案 | 无业务逻辑 |
| `src/backend/local.ts` | 本地模式的查询构造器与设备 RPC | 与云端 SQL 语义对齐 |
| `src/views/*` | 三种视图 | 视图内只管交互与绘制 |
| `src/components/*` | 导航、详情面板、设置、通用控件 | — |
| `src/styles.css` | 设计 token + 全部样式 | 单文件，无 CSS-in-JS |

## 数据流

```
用户操作 → data.ts 写库 → pull() 拉增量 → merge() → store 更新 → 视图重绘
```

`merge()` 有两个刻意为之的细节：

1. **没有增量就不生成新数组**。否则每次轮询都会让依赖 `data` 的图重建一次，力导向布局会不停复位。
2. **合并时校验选区**。节点被其它设备删掉后，`selected` / `focusIdentity` 自动置空，避免详情面板指向不存在的行。

## 同步循环

```ts
startSync() {
  pull()                                  // 立刻一次
  setInterval(pull, 1500)                 // 仅在页面可见时执行
  visibilitychange → pull()               // 切回来立刻一次
  BroadcastChannel('second-mind') → pull() // 同浏览器多标签
}
```

写入后调用 `poke()`：向其它标签页广播，并立即 `pull()` 一次以拿到服务端分配的 `id` 与 `rev`。

本地模式同样跑这个循环——只是后端在内存里，`pull()` 几乎无成本，于是「两种模式行为一致」不需要写两套代码。

## 渲染

**Network**：Canvas 2D，`devicePixelRatio` 上限 2.5。每帧只画可视范围内的节点与边。三种视觉状态：

| 状态 | 条件 | 表现 |
|---|---|---|
| 静息 | 默认 | 一级身份球显示名字；其余为小点 |
| 邻近 | 指针进入 28px | 该簇（节点 + 一环邻居）显示名字，其余降到 18% 透明度 |
| 聚焦 | 选中 | 保持展开，直到切换选区 |

进入有 120ms 停留判定，离开有 180ms 延迟——快速划过不会让标签乱闪。

**Board**：真实 DOM 绝对定位 + SVG 连线层。拖动用 Pointer Events，拖动过程只改本地状态，`pointerup` 时才落库，避免每帧写一次。

**Outline**：语义化 `<ul>` + 折叠按钮，键盘可达。

## 主题

所有颜色走 CSS 变量，`data-theme` 挂在 `<html>` 上。切换主题只是换一组变量，不需要重载组件。Canvas 读不到 CSS 变量，所以绘图前用 `getComputedStyle` 取一次当前色板并缓存，主题变化时重取。

对比度按 WCAG 2.2 AA 核算，浅色版三级灰从 `#8A90A0`（2.98:1）调到 `#6A7180`（4.57:1）就是为了达标。

## 性能

| 项 | 当前 | 上限 |
|---|---|---|
| 首屏 JS | 371 KB / gzip 115 KB | 未做路由级拆分（单页，收益有限） |
| 节点规模 | 建议 ≤ 数千 | Canvas 而非 WebGL，万级需换渲染后端 |
| 布局计算 | 主线程 | 万级应移入 Web Worker |
| 轮询 | 1.5s，页面隐藏时暂停 | 真推送需换后端 |

## 扩展点

- **换后端**：实现 `src/backend/local.ts` 里那套链式方法（`from/select/insert/update/eq/in/is/gt/order/range/limit`）即可；`data.ts` 不动。
- **加节点类型**：`types.ts` 的 `Kind` + `KIND_LABEL`，再在工作台的加号菜单里注册。
- **加视图**：`store.ts` 的 `View` 联合类型 + `App.tsx` 一处分支。视图只读 store、只调 `data.ts`。
- **端到端加密**：把 `data.ts` 的标题/正文读写包一层加解密即可；坐标与结构需要留明文，否则布局要全量解密。
