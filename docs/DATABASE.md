# 数据模型

四张表，一份可增量同步的图。完整 DDL 见 [`schema.sql`](schema.sql)。

## 为什么是这四张表

| 表 | 一行代表 | 关键点 |
|---|---|---|
| `identities` | 一个身份词（第一级神经元） | 有坐标 `x/y`，工作台里拖过之后位置固定 |
| `nodes` | 身份词下的一个内容节点 | `identity_id` 归属，`parent_id` 支持多层 |
| `edges` | 一条连接 | 两端各带 `kind`，因此可以连节点，也可以连身份词 |
| `devices` | 一台受信任的浏览器 | 3 台上限、15 天窗口的载体 |

## 三个设计决定

**1. `rev` 是同步的唯一游标**

全局序列 `sm_rev_seq` 在 `BEFORE INSERT OR UPDATE` 触发器里取值写进 `rev`。客户端只记一个数——见过的最大 `rev`——然后每 1.5 秒问一次「`rev` 比我大的是什么」。不需要逐表时间戳比较，也不会因为时钟漂移漏数据。

**2. 删除是软删**

写 `deleted_at` 而不是 `DELETE`。原因有三个：删除本身也要通过 `rev` 同步到其它设备（否则别处的副本永远删不掉）、删除可撤销、`rev` 游标不会被物理删除打乱。客户端在合并时把带 `deleted_at` 的行从内存里移除。

**3. 连线两端各存一个 `kind`**

`identities.id` 和 `nodes.id` 来自两个独立序列，必然撞号。只有 `source_id = 3` 无法判断指的是哪个身份词还是哪个节点。所以 `source_kind` / `target_kind` 是必需列，不是冗余。

## 字段约定

### nodes.kind

| 值 | 含义 | 额外字段 |
|---|---|---|
| `skill` | 技能 | — |
| `step` | 步骤 | — |
| `progress` | 进度 | `progress` 0–100 |
| `todo` | 待办 | `status`: `open` / `done` |
| `note` | 笔记 | `note` 长文本 |
| `question` | 疑问 | — |

### 坐标

`x` / `y` 是**工作台**里的位置（相对内容区左上角），不是 Network 的坐标。Network 每次由力导向布局计算，不落库——这样同一份数据在不同屏幕上都能得到合适的结果。

## 行级隔离

每张表都启用 RLS，策略统一为 `owner_id = auth.uid()`：

- `owner_id` 列默认值就是 `auth.uid()`，插入时不用传
- 未登录时 `auth.uid()` 为 `NULL`，比较恒不成立，服务端不返回任何行
- 越权写入在 `WITH CHECK` 处直接失败（错误码 `42501`）

客户端不能、也不需要自己过滤 `owner_id`——那是数据库的责任。

## 设备裁决

`sm_claim_device(p_key, p_label, p_platform)` 返回三种状态：

| status | 含义 | 客户端行为 |
|---|---|---|
| `ok` | 已信任，返回 `device_id` 与 `expires_at` | 继续加载数据 |
| `limit` | 已有 3 台活跃设备，返回列表 | 弹窗要求注销一台，否则不允许继续 |
| `unauthenticated` | 没有有效会话 | 回到登录页 |

`device_key` 是浏览器生成并存在本地的 UUID。它**不是**硬件指纹：清站点数据就会变，换浏览器也会变。这是 Web 平台的能力边界，不要把它当安全边界用——安全边界在会话令牌与 RLS 上。

## 迁移

结构变更请新增文件（`docs/migrations/0002_xxx.sql`）而不是改 `schema.sql` 的历史语句，便于已有部署按序升级。当前版本即为 `0001`。

`schema.sql` 本身幂等，重复执行不会报错，适合新环境一键初始化。
