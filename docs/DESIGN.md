# second mind — 设计方案 v1.0

> 一句话：**一个用神经元网络来梳理"我是谁"的第二大脑。**
> 身份词是第一级神经元，技能 / 步骤 / 待办是它伸出的突触；你只在自己靠近时，才看见突触上的细节。

**产品形态**：Web（移动优先，PWA 可安装）· **开源协议**：MIT · **核心视图**：Network（全局网络）/ Board（身份工作台）

---

## 1. 核心隐喻与设计立场

| 维度 | 隐喻 | 对设计的约束 |
|---|---|---|
| 结构 | 神经元网络 | 节点不做整齐网格排列，允许有机分布；连线是主角，不是装饰 |
| 注意力 | 显微镜 | 默认只看第一级；细节靠"靠近"唤醒，而非"点击" |
| 时间 | 生长 | 新增节点有生长动效；删除有淡出+归位，不留突兀空洞 |
| 语气 | 安静的工具 | 无红点、无推送、无打卡。动效克制，颜色低饱和 |
| 私密 | 只有你能看 | 未登录时服务端**不返回任何数据**，而不是前端隐藏 |

**品牌**：字标 `second mind` 全小写，字母 `i` 的点替换为一颗发光节点；图标为"两环 + 三点"的神经元简笔。

## 2. 信息架构

三层结构，层级即权限与同步的边界：

```
账号（手机号）
└── 身份词 identity  ← 第一级节点，用户自建、可删
    └── 内容节点 node（skill / step / progress / todo / note / question）
         └── 任意节点之间可建 reference 链接（可跨身份词）
```

**三个视图**

1. **Network（主页）** — 全量图谱。第一级球显示身份词名称，二级以下只显示小点，鼠标邻近才展开。
2. **Board（工作台）** — 单个身份词的搭建画布。增删节点、拖拽连线、勾待办、改进度。
3. **Outline（大纲）** — 与 Network 同数据源的列表/树视图。键盘完全可操作，也是无障碍旁路。

导航：左侧身份词栏（Rail）常驻 → 点击进入 Board；Network 是默认落地页；Outline 由 `⌘/Ctrl + Shift + O` 或左上角视图切换唤起。

## 3. 数据模型

```sql
users        (id, phone_hash, phone_enc, created_at, status)
devices      (id, user_id, name, ua, platform, created_at,
              last_seen_at, expires_at, revoked_at, token_hash)
otp_codes    (id, phone_hash, code_hash, purpose, expires_at, attempts, consumed_at)

identities   (id, user_id, name, color_key, sort_order, archived_at)
nodes        (id, user_id, identity_id, parent_id, kind, title, note,
              status, progress, x, y, pinned, created_at, updated_at, archived_at)
edges        (id, user_id, source_id, target_id, kind, label)

layout       (user_id, node_id, x, y, pinned)   -- 布局与内容分离，便于"重新排布"
yjs_updates  (user_id, seq, update bytea, created_at)  -- CRDT 增量日志
```

**节点类型 `kind`**：`identity` / `skill` / `step` / `progress` / `todo` / `note` / `question`
**边类型 `kind`**：

- `hierarchy` — 父子归属（一个节点只有一个父，决定树的形状）
- `reference` — 跨节点引用，"这个技能支撑那个身份"。**允许多对多，允许指向身份词本身**
- `sequence` — 步骤先后顺序（同层级内的流程）

> 设计要点：`hierarchy` 撑起骨架，`reference` 制造"网"。没有 reference 就只是树，用户要的"神经元感"来自 reference 的交叉。

**软删除**：所有内容表用 `archived_at` 而非物理删除，配合 30 天回收站与撤销 Toast（防误删，也避免 CRDT 墓碑冲突）。

## 4. 认证与设备信任

### 4.1 流程

```
未登录（只看到品牌页 + 手机号输入）
  → 输入手机号 → 发送验证码（60s 冷却 / 5 分钟有效 / 单条一次性）
  → 输入 6 位码（错误 5 次锁定 15 分钟）
  → 校验通过
      ├─ 已有设备：签发新设备令牌
      │     └─ 若已达 3 台 → 强制选择一台注销（列出设备名 / 最近活跃时间）
      └─ 新用户：创建账号 + 预置 3 个示例身份词（可一键清空）
  → 写入 httpOnly Cookie `mind_session`（15 天，Secure, SameSite=Lax）+ deviceId
  → 进入 Network
```

### 4.2 15 天免登录

- **固定窗口**，不滑动续期：第 15 天 00:00 失效，重新验证手机号。滑动续期会让令牌事实上永不过期，不做。
- 剩余 ≤ 2 天时，顶部出现一条可关闭的细提示条："登录状态将于 3 天后失效"，附"现在延长"。
- 二次进入浏览器：`GET /api/session` 静默恢复，无感知、无 loading 闪烁（用骨架屏顶住 200ms）。

### 4.3 必须诚实说明的安全边界

> Web 端**无法真正绑定硬件**。所谓"绑定设备"，本质是一枚 15 天有效、与设备指纹弱绑定的刷新令牌。任何人拿到这枚令牌（例如导出浏览器存储），就能以你的身份访问。
>
> 因此方案里补三道防线：
> 1. 令牌仅存 httpOnly Cookie，JS 读不到（降低 XSS 窃取面）
> 2. 设备列表可随时查看与远程注销（设置 → 设备与登录）
> 3. 导出全部数据、注销账号等敏感操作，需**再次验证手机号**
>
> 如果这个边界对你不可接受，唯一彻底的解法是端到端加密（见 §6 方案 B）。

### 4.4 防滥用

IP 每小时 10 次、单号码每天 5 次发送上限；验证码只存哈希；响应时间恒定（防时序枚举手机号是否注册）。

## 5. 实时同步

- **引擎**：Yjs CRDT。整个用户空间一个 `Y.Doc`，节点为 `Y.Map`、边为 `Y.Array`。
- **传输**：Hocuspocus WebSocket。房间名 `user:{userId}`，`onAuthenticate` 校验设备令牌有效期与撤销状态——**令牌失效即断开**，不是等下次请求。
- **持久化**：增量 update 落 `yjs_updates`，每 200 条或 10 秒做一次快照；冷启动从快照 + 增量重建。
- **冲突**：CRDT 自动合并文本；**删除优先于编辑**——A 删、B 改同一节点时，以删除为准，B 端弹出"该节点已在其他设备删除"并保留 5 秒撤销。
- **离线**：IndexedDB 持久化，断网可继续编辑，恢复后自动合并。顶部细条提示"离线中 · 改动已暂存"。
- **在线感知**：awareness 显示"另一台设备正在编辑"。默认开启，设置里可关（有人喜欢，有人觉得被盯着）。

**布局稳定性**：力导向每次重开都漂移会毁掉空间记忆。做法是坐标 `pinned` 优先，只有新节点参与局部松弛，提供显式"重新排布"按钮。

## 6. 隐私与账号隔离

| 层 | 措施 |
|---|---|
| 传输 | 全站 HTTPS / WSS，HSTS |
| 接口 | 所有读写强制 `user_id` 来自会话，**永不信任请求体里的 user_id** |
| 数据库 | Postgres Row Level Security，策略 `user_id = current_setting('app.user_id')` |
| 实时 | 房间按 user 隔离，订阅他人房间直接拒连 |
| 未登录 | API 一律 401，页面不渲染任何节点数据（不是 CSS 隐藏） |
| 静态 | 数据库磁盘加密；备份文件加密且不含手机号明文（只存 hash + 加密列） |

**加密方案取舍（需要你拍板）**

- **方案 A（推荐起步）**：服务端隔离 + RLS + 磁盘加密。体验完整，忘记密码可凭手机号找回。
- **方案 B（可后续开启）**：客户端 WebCrypto 加密节点标题与正文，密钥由恢复码派生（Argon2id），服务端只存密文。代价：**恢复码丢失 = 数据永久不可恢复**；服务端无法全文搜索；换设备必须输入恢复码。

架构上把 `title/note` 的读写封装成可插拔加密层，A → B 不需重构。

## 7. Network 视图交互规格（核心）

### 7.1 三态

| 状态 | 触发 | 画面 |
|---|---|---|
| **静止态** | 默认 / 鼠标离开 | 仅第一级球显示身份词（14px/600）；二级以下为 3px 小点，无标签；其余全部同亮度 |
| **邻近态** | 指针进入节点 28px 半径并停留 120ms | 唤醒该节点 v 及其一环邻居 `S = {v} ∪ ring1(v)`：显示标签、放大到 5px、加光环；非相关节点降至 18% 透明度 |
| **聚焦态** | 点击 | 摄像机 flyTo 该节点，右侧打开检查器；Board 入口出现 |

`ring1(v)` = 父节点 + 所有子节点 + reference 出边邻居 + reference 入边邻居。**只展开一环**，避免信息爆炸。

### 7.2 邻近命中的细节（这些决定的成败）

- **命中半径**：屏幕恒定 28 逻辑像素（`28 / zoom`），缩放时手感一致。
- **停留阈值 120ms**：快速划过不触发，避免标签疯狂闪烁。
- **收起延时 180ms**：从节点移向它的邻居时不至于瞬间黑掉。
- **多目标冲突**：取距离最近；距离差 < 6px 时取内容更多（度数更高）的那个。
- **触屏**：长按 200ms = 邻近态；轻点 = 聚焦态；双指缩放；点空白收起。移动端另给 Board 入口，不强迫在小屏上做精细悬停。
- **降级**：`prefers-reduced-motion` 时不播放光环扩散，仅做透明度切换。

### 7.3 细节层级（LOD）

| 缩放 | 表现 |
|---|---|
| `z < 0.5` | 只画第一级球与标签；二级以下合并为雾状点云（降低绘制量） |
| `0.5 ≤ z < 1.6` | 默认：点 + 邻近展开 |
| `z ≥ 1.6` | 可选"全部显示标签"开关，适合整理时纵览 |

### 7.4 性能预算

目标：**MacBook Air M1 上 5000 节点 / 8000 边稳定 60fps**。

- 力导向跑在 Web Worker，30fps 回传坐标，主线程 60fps 插值渲染
- 空间哈希网格（cell 48px）做 O(1) 邻近查询，不做全量距离遍历
- 边按颜色分组、用单条 `Path2D` 批量描边
- 标签最多同时绘制 80 个，超出按度数截断
- 超过 8000 节点时提示"建议拆分身份词"，并自动进入简化渲染

### 7.5 视觉语言

- 第一级球：半径 22–34px 随内容量增长（`18 + 4·√degree`，上限 40），填色取身份色，中心留白 1px 描边做"细胞感"
- 二级点：3px，取父身份色的 60% 明度
- 边：`hierarchy` 为 1px 实线，`reference` 为 1px 虚线 + 端点小箭头；透明度 0.22，唤醒时 0.55
- 背景：浅色版是极浅的纸面网格（24px 点阵，2% 浓度）；深色版是径向暗角，无网格
- 呼吸：第一级球 `scale 1 → 1.02`，4s，仅在无交互 3 秒后启动

## 8. Board 工作台

进入：从 Network 点击第一级球，或左侧身份词栏。

- **布局**：身份词作为锚点居中偏左，右侧自动分四列（技能 / 步骤 / 待办 / 笔记）；列内纵向流动，可手动拖到任意位置
- **卡片**：标题（14px/500）+ 类型图标 + 子节点计数 + 进度环（仅 progress）；待办卡片带真复选框
- **建连**：卡片右侧出现锚点，拖出橡皮筋线 → 落到任意节点或左侧身份词即建立 `reference`；松开在空白处则弹出"新建节点并连接"
- **快捷操作**：`Enter` 新建同级 · `Tab` 新建子级 · `Delete` 删除（Toast 可撤销）· `⌘K` 命令面板
- **检查器**：右侧 320–360px 面板，改名 / 换色 / 类型 / 进度 / 备注 / 关联列表 / 删除

- 阴影（深色）：**不用阴影**，改用 `1px` 描边 + 顶部 1px 内高光（`inset 0 1px 0 rgba(255,255,255,.04)`），避免灰雾

## 12. 无障碍

- **Canvas 的旁路是硬性要求**：图谱本身对键盘/读屏不可用，因此提供同数据源的 **Outline 视图**（语义化 `ul`/树），键盘可完成全部操作。两者切换时焦点位置保持。
- 焦点环：`2px solid` 主色 + `2px` 偏移，任何情况下不被 `outline: none` 移除
- 触控目标 ≥ 44×44px（小点节点在触屏上给不可见的 44px 热区）
- `aria-live="polite"` 播报"已新增'吉他'节点""已与'设计师'建立连接"
- 标题层级严格 h1→h2→h3，不跳级
- 所有图标按钮带 `aria-label`
- 对比度见 §9.1，正文全部 ≥4.5:1

## 15. 风险与取舍

| 风险 | 说明 | 对策 |
|---|---|---|
| "无限节点"与性能天然冲突 | 力导向是 O(n log n) 但渲染受标签拖累 | LOD + Worker + 点云降级；8000 节点给出引导 |
| 触屏没有 hover | 邻近展开在手机上不存在 | 长按 200ms 替代 + 移动端主推 Board |
| 图谱易"越用越乱" | 力导向漂移破坏空间记忆 | 坐标持久化 + 局部松弛 + 手动重排 |
| 15 天信任的安全边界 | Web 无法真绑硬件 | 令牌 httpOnly + 设备可远程注销 + 敏感操作二次验证 |
| E2EE 与"手机号找回"互斥 | 加密后服务端无法代你恢复 | 方案 A 起步，加密层可插拔 |
| 短信成本与滥用 | 每条短信真实计费 | 限流 + 冷却 + 可选图形验证码；自托管可换邮件/Passkey |
| 悬停展开可能"太聪明" | 用户没预期标签自己出现 | 120ms 停留阈值 + 首次使用时一次 3 秒引导动效 |

## 17. 落地记录（实现后的修订，v1.1）

你拍板的是：**WorkBuddy 云服务托管 + 服务端隔离 + 全栈可部署 + 开发模式验证码**。实现过程中有几处必须修正，如实记在这里。

| 原方案 | 实际落地 | 原因 |
|---|---|---|
| Yjs + WebSocket 实时推送 | **1.5s 增量轮询 + BroadcastChannel** | 云数据库是 PostgREST 风格，没有订阅通道。延迟 1–2 秒，不是零；同浏览器多标签页是即时的。 |
| 短信走"开发模式" | **平台自带短信通道** | 验证码由云服务统一发送，不需要你购买短信服务商账号，也就没有"开发模式"这个选项。 |
| `edges.source_id` 直接指向 | **增加 `source_kind` / `target_kind`** | 节点 id 与身份词 id 从各自序列自增，必然撞号。跨身份连线必须带类型才能解析。 |
| 15 天固定窗口 | 保持固定窗口，**服务端 RPC `sm_claim_device` 裁决** | 3 台上限与过期清理放在数据库函数里，前端只负责展示。 |
| 布局跑在 Web Worker | 暂在主线程（d3-force，alpha 衰减后自动停止） | 个人规模图谱够用；万级节点再迁移。已写进 README 的 Roadmap。 |
| "重新排布"= 重新力导向 | 需要对初始坐标加随机抖动 | 布局是确定性的（为了空间记忆稳定），不加抖动点了按钮不会有任何变化。 |
| 检查器改字段即写库 | **失焦/回车才提交** | 防抖写入会在切换节点时把 A 的标题写到 B 上——这是真实存在过的缺陷。 |

**额外的产品决定**

- 新增「大纲视图」并放进主导航，不是隐藏功能。Canvas 图谱对键盘与读屏天然不可用，必须有等价入口。
- 删除一律软删，为后续回收站与撤销留出空间。
- 关闭设备上限弹窗 = 放弃本次登录（直接登出），避免"超限但仍在用"的模糊状态。
